# Masaru and Manami – 5th Anniversary Party 招待状

結婚5周年パーティーのWeb招待状です。GitHub Pagesで公開し、出欠確認（RSVP）はGoogle Apps Script（GAS）経由でGoogleスプレッドシートに記録します。

## ファイル構成

```
invitation/
├── index.html        … ページ本体(HTML)
├── Invitation.css     … デザイン(CSS)
├── Invitation.js      … 動き・送信処理(JavaScript)
├── コード.gs           … GAS側のスクリプト（スプレッドシートに書き込む）
├── README.md          … このファイル
└── images/            … 写真・画像を置くフォルダ（今はプレースホルダー画像が入っています）
```

## 画像の差し替え方法

`images/` フォルダの中の以下のファイルを、同じファイル名のまま実際の写真に差し替えてください（拡張子 `.jpg` のまま、正方形/縦長など元のサイズ比に近いものだとレイアウトが崩れにくいです）。

| ファイル名 | 使われている場所 | 推奨サイズ目安 |
|---|---|---|
| `hero1.jpg`〜`hero3.jpg` | オープニングの写真3枚（縦並び） | 縦長 (例: 900×1200px) |
| `countdown-bg.jpg` | カウントダウンの背景写真（全面表示） | 横長 (例: 1600×1200px) |
| `message-bg.jpg` | メッセージの背景写真（全面表示） | 横長 (例: 1600×1200px) |
| `groom-front.jpg` / `groom-back.jpg` | 新郎プロフィールのコイン表裏 | 正方形 (例: 800×800px) |
| `bride-front.jpg` / `bride-back.jpg` | 新婦プロフィールのコイン表裏 | 正方形 (例: 800×800px) |
| `gallery1.jpg`〜`gallery5.jpg` | 自動＆ドラッグで流れるギャラリー写真 | 縦長 (例: 800×1000px) |
| `info-bg.jpg` | パーティー情報〜ご案内の共通背景写真 | 縦長 (例: 1200×2000px、木目やグリーンなど落ち着いた質感がおすすめ) |
| `guidance-number-bg.jpg` | ご案内(01/02/03)の番号バッジの背景テクスチャ | 正方形の小さめ画像でOK (例: 200×200px) |
| `rsvp-mark.png` | 出欠(ご出席/ご欠席/保留)ボタンに表示される丸印 | 透過PNG・正方形推奨 (例: 240×240px) |

画像を追加・削除したい場合は、`index.html` 内の `<img src="images/...">` の行を増減し、`Invitation.css` の `.hero-gallery` や `.gallery-track` のスタイルと合わせて調整してください。

## GAS（Google Apps Script）側の設定

1. 出欠データを貯めたいGoogleスプレッドシートを開く
2. `拡張機能 → Apps Script` を開く
3. 中身をこのリポジトリの `コード.gs` の内容に置き換える（シート名が「シート1」以外なら `SHEET_NAME` を変更）
4. `デプロイ → デプロイを管理 → 編集(鉛筆アイコン) → バージョン: 新バージョン → デプロイ`
   - **これを忘れると、コードを直しても公開中のURLに反映されません**
5. 発行された `.../exec` のURLが、`Invitation.js` 内の `GAS_URL` と同じであることを確認する
   （すでに同じURLを使う前提で設定済みです。URLを変更した場合は `Invitation.js` の `GAS_URL` も書き換えてください）

## GitHub Pagesでの公開手順

1. このフォルダの中身（`index.html` / `Invitation.css` / `Invitation.js` / `images/` フォルダなど）をリポジトリのルート（またはお好きなフォルダ）にそのままアップロードする
2. リポジトリの `Settings → Pages` を開く
3. `Source` を `Deploy from a branch` にし、対象のブランチとフォルダ（例: `main` ブランチ / `/root`）を選んで保存
4. 数分後、`https://ユーザー名.github.io/リポジトリ名/` でアクセスできるようになります

## Figmaからの実装手順（おすすめの進め方）

今回は以下の順番で進めました。同じような修正・追加をする際も、この順番だと迷いにくいです。

1. **Figmaの各セクションをスクリーンショットで書き出す**（実測のpx単位で追う必要はなく、色・フォント・余白感・要素の並び順を把握するのが目的）
2. **配色とフォントをCSS変数に落とし込む**（`Invitation.css` 冒頭の `:root { --color-... }` の部分）。ここを最初に決めておくと、後の作業で色がブレません
3. **セクションごとにHTMLの骨組みだけ作る**（文章や画像はダミーでOK。まず「箱」を並べる）
4. **セクションごとにCSSで見た目を整える**（1セクションずつ完成させてから次へ進むと、崩れた時の原因を切り分けやすいです)
5. **最後に動き(アニメーション)を足す**（封筒開封・コイン反転・マーキーなど）。先に静止画の状態で完成させてから動きを足すと、レイアウト崩れと動きの不具合を同時に追わずに済みます
6. **フォームとGAS連携を実装・テスト送信**
7. **実際の写真に差し替え**て最終チェック

## 開発時の注意点

- ブラウザで直接 `index.html` をダブルクリックして開くと、一部のブラウザでは `fetch` がうまく動かないことがあります。ローカルで動作確認する場合は `VS Code の Live Server拡張` などの簡易サーバーを使うのがおすすめです。
- スマートフォンでの見え方を必ず確認してください（Chrome DevToolsの「デバイスモード」やご自身のスマホから実際にアクセスするなど）。
